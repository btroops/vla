# P00 踩坑记录

> 完整源码级分析见 `notes/2026-11-23-wsl2-mujoco可视化方案.md`（仓库根目录的 notes/）。
> 这里只记现象和结论。

## 坑 1：viewer 开窗闪退，整个 WSL 会话崩掉

- 现象：运行 `mujoco.viewer.launch_passive` 窗口闪一下就退出，终端提示符从 `btroops@...:~$` 变成 `C:\Users\btroops>`，整个 WSL 被带崩，得 `wsl --shutdown` 恢复。
- 根因：WSLg 的 OpenGL 转发与 GLFW 不兼容；和代码无关。
- 解决：放弃 viewer，改用 meshcat 浏览器方案。
- 教训：WSL2 下做 MuJoCo 可视化，默认就走离屏渲染或 meshcat，别碰原生窗口。

## 坑 2：`MUJOCO_GL=egl / osmesa` 对 viewer 开窗无效

- 现象：设了这两个环境变量，viewer 照样崩。
- 根因：这俩变量只控制 MuJoCo 离屏渲染（`mujoco.Renderer`）的后端，viewer 走的是 GLFW + 系统 OpenGL，根本不读它们。
- 教训：搞清楚环境变量管的是哪条路径，别瞎试。

## 坑 3：meshcat 页面只有网格没有球

- 现象：浏览器能打开页面、看到网格和坐标轴，但没有几何体。
- 根因：脚本 8 秒就跑完退出，zmq 服务器关了，浏览器只加载了默认场景。
- 解决：脚本改无限循环，服务器常驻，刷新浏览器。
- 教训：看到页面 ≠ 连上了数据源，先确认服务端进程还活着。

## 坑 4：地面变成一堵竖直的墙

- 现象：第一版 bridge 里，给父节点设了 z-up→y-up 旋转，地面却竖起来了。
- 根因：meshcat 的 `set_transform` 直接设世界坐标，不叠加父节点变换。
- 解决：把 `ZUP_TO_YUP @ T_mujoco` 乘进每个 geom 的位姿里。
- 教训：搞清楚 API 是"相对父节点"还是"世界坐标"，别靠猜。

## 坑 5：摆杆平躺、朝向不对

- 现象：摆杆水平躺着，而不是竖直悬挂。
- 根因：Three.js 的 Cylinder 默认沿 y 轴，MuJoCo 的 capsule 沿 z 轴。
- 解决：位姿矩阵右乘 `R_FIX`（局部旋转），把几何体轴向对齐。
- 教训：几何体的"默认朝向"和物理引擎的约定不一样，要显式对齐。

## 坑 6：落体场景看起来"静止"

- 现象：自由落体球 0.5 秒就落地停住，打开浏览器时早就不动了。
- 根因：不是同步失败，是物理已经结束。
- 解决：换成带铰链 + 阻尼 + 初始角速度的摆，随时打开都在动。
- 教训：验证"动起来"要用持续运动的系统，别用一次性落体。

## 坑 7：手动设相机反而视角更差

- 现象：写了 look-at 相机矩阵，视角变成几乎平视（网格像墙）；不设反而默认视角很好。
- 根因：meshcat 默认相机由浏览器端 OrbitControls 管理，手动设要抵消父节点旋转，还要算对俯角。
- 解决：删掉相机代码，用默认视角（斜上方俯视）。
- 备份：`src/mujoco_meshcat_bridge_user.py` 保留了手动设相机的版本，可作对照。
- 教训：默认配置往往是调过的，先别急着覆盖它。
