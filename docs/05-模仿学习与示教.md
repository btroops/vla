## 正文

### 1. 直觉：不会写规则，那就做给它看

[04](./04-强化学习与机器人.md) 里的强化学习靠"试错 + 奖励"。但真机上试错很贵：机械臂乱动可能撞坏东西、抓碎杯子、甚至碰到人。而且很多任务的好奖励根本写不出来——"把毛巾叠整齐"怎么量化？

**模仿学习（Imitation Learning, IL）** 换个思路：**不写规则、不设计奖励，直接让人类演示，机器照着学**。类比：教小孩写字，你不会先定义"笔画的奖励函数"，而是握着他的手写几遍。

形式上，我们拿到一批示教数据：

$$
\mathcal{D} = \{(\underbrace{o_i}_{\text{观测}},\, \underbrace{a_i}_{\text{当时人类做的动作}})\}_{i=1}^{N}
$$

目标是学一个策略 $\pi_\theta(a\mid o)$ 让它在同样观测下做出和人类相似的动作。**本质上这是监督学习**——这也是它样本效率高、工程上友好的根源。

对照 04 篇的表格看会更清楚：

| 维度 | 强化学习 | 模仿学习 |
|---|---|---|
| 数据来源 | 自己试错 | 人类示教 |
| 需要什么 | 好奖励函数 | 好演示数据 |
| 样本效率 | 低（百万级交互） | 高（几百条示教常够） |
| 能力上限 | 可能超过人类 | 大致受限于示教水平 |
| 主要失败模式 | 奖励黑客、不稳定 | **分布偏移**、对未见场景脆弱 |
| 真机安全性 | 差（需围栏） | 好（演示本身就是安全的） |

### 2. 示教数据从哪来

数据是这个领域最贵的东西。常见采集方式：

| 方式 | 怎么做 | 优点 | 缺点 |
|---|---|---|---|
| **动觉示教（kinesthetic teaching）** | 人直接抓住机械臂拖动，同时记录关节角 | 无需额外硬件，直观 | 只能采集慢动作；力觉无法记录；只适合轻载臂 |
| **主从臂 / leader-follower** | 一台小臂（leader）被人操作，另一台（follower）同构跟随并记录 | 力反馈自然、动作精细（ALOHA 采用） | 要两套臂；主从标定与延迟 |
| **VR / 手柄遥操作** | 手部或手柄位姿映射到末端位姿 | 人机分离、可采高难度动作 | 缺乏力觉、易抖、需 IK 与安全限幅 |
| **动捕 / 外骨骼** | 采集人体动作再重定向到机器人 | 动作自然、数据量大 | 需重定向（retargeting），人机结构差异大 |

**采集时最影响成败的四个细节**（比模型选型更影响结果）：

1. **相机配置要固定且多样**：几个相机、装在哪、内参焦距，必须在整个数据集里一致；但**演示之间的初始位姿、物体位置要刻意打散**，否则模型只学会"记住唯一那条轨迹"。
2. **控制频率与动作标注对齐**：图像时间戳和动作时间戳差几十毫秒，学出来的策略就会"看着上一帧做当前动作"，表现为系统性滞后。
3. **动作标注的语义要写清**：记录的是关节位置、末端位姿增量，还是绝对位姿？有没有除以控制周期变成速度？**这一项写错，数据等于废掉**。
4. **包含失败与纠错的片段**：只留完美演示，模型就没见过"偏了之后怎么回来"，这是后面分布偏移的直接来源。

### 3. 行为克隆与分布偏移：一切问题的起点

**行为克隆（Behavior Cloning, BC）** 就是最朴素的监督学习：

$$
\theta^\star = \arg\min_\theta \; \mathbb{E}_{(o,a)\sim\mathcal{D}}\big[\,\|\pi_\theta(o) - a\|^2\,\big]
$$

看起来毫无问题。但机器人是个**闭环序列决策**问题，而 BC 把它当成了一堆独立样本——这就是灾难的开始。

**分布偏移（distribution shift，也叫协变量偏移 covariate shift）的机制**：

1. 训练时，模型看到的观测 $o$ 全部来自**人类产生的轨迹**（专家分布）。
2. 部署时，模型自己的动作有微小误差，机器人稍微偏离了专家轨迹。
3. 于是它进入了一个**训练时从没见过的状态**（专家从不到那里去）。
4. 在这个陌生状态上，模型输出变得更离谱 → 偏得更远 → 进入更陌生的状态。
5. **误差自我放大**，直到彻底失败。

理论分析（Ross 等，DAgger 论文）给出的直觉结论是：若单步误差为 $\epsilon$、时长 $T$，BC 的累计代价量级是 $O(\epsilon T^2)$，而"边做边纠"的方法可以把量级降到 $O(\epsilon T)$。虽然这是在一定假设下（如系统稳定、分布混合良好）的结论，但机制与实验现象一致：**BC 的失败常常不是"动作不像"，而是"稍微偏了就再也没回来"**。

生活化类比：只会背答案的学生，遇到一道稍微改过数字的题就不会做了；而且他越做越慌，后面整张卷子全崩。

**工程上缓解分布偏移的常用手段**：

- **数据增广**：在示教图像上做随机裁剪、颜色抖动、加噪声；更有针对性的是**在示教状态附近人为注入小扰动**并记录专家的纠正动作。
- **多模态输入**（图像历史、本体状态、上一动作）：让模型知道"我偏了"，从而有纠正的依据。**只给单帧图像的 BC 几乎必然出现漂移。**
- **动作分块**（见第 5 节）：一次预测一段，减少推理次数，从而减少误差累积机会。

### 4. DAgger：边跑边问老师

**DAgger（Dataset Aggregation）** 的解法直击要害：**既然问题是"部署时看到了训练时没见过的状态"，那就把这些状态采出来，让专家标注**。

流程（迭代执行）：

```
1. 用当前示教数据训练策略 π_i
2. 让 π_i 在真实环境里自己跑，记录它访问到的状态序列
3. 请专家（人）为这些状态标注"换了我，这时该做什么动作"
4. 把新标注的数据合并进数据集：D ← D ∪ D_new
5. 重新训练，回到第 2 步
```

核心洞察：**训练分布必须等于部署分布**。DAgger 把"策略真正会去的状态"逐步纳入训练集，理论上可直接达到 $O(\epsilon T)$ 的代价。

**为什么真机上很难做**：它要求专家在机器人**执行过程中**持续在线纠错。真机上这意味着：要有人一直盯着、要能随时接管、要低延迟、而且机器人一旦因为奇怪的策略动作进入危险姿态还得先救回来。于是实践中常做妥协：只在仿真里跑 DAgger、或用"人看着回放手动标注"近似、或干脆接受 BC + 保守的动作限幅。

**旁支**：**逆强化学习（Inverse Reinforcement Learning, IRL）** 与 **GAIL** 走的是另一条路——**从示教中反推出奖励函数**，然后用 RL 学策略。好处是学到的策略可以超出示教水平；坏处是训练不稳定、实现复杂，工程上不如 BC 系方法普及。

### 5. 现代模仿学习的四个关键改进

#### 5.1 动作分块（action chunking）

不要每一步都预测一个动作，而是一次预测未来 $k$ 步：

$$
\pi_\theta:\; o_t \;\longmapsto\; \hat{a}_{t:t+k} = (\hat a_t, \hat a_{t+1}, \dots, \hat a_{t+k-1})
$$

执行时把这 $k$ 步跑完再重新推理。**它同时解决两个问题**：

- **推理延迟**：设一次前向（含视觉编码）耗时 $\Delta$、控制周期 $1/f$。单步输出要求 $\Delta < 1/f$，而输出 $k$ 步只要求 $\Delta < k/f$——**实时性预算被放大 $k$ 倍**。对大模型来说这是决定性的。
- **复合误差**：段内动作是**联合生成**的，时间上更自洽（不会出现"第 3 步往左、第 4 步往右"），且推理次数减少 $k$ 倍，漂移机会随之减少。

**代价**：块内是开环的——这 $k$ 步里杯子被人挪了、抓滑了，模型看不见也反应不了。缓解手段：

- **时间集成（temporal ensembling）**：相邻两次推理的重叠部分加权平均。
- **滚动重推理（receding horizon）**：只执行前 $m$ 步（$m<k$）就重新推理。
- **块边界平滑**：对衔接处做插值或低通滤波，避免跳变。

一句话：**用"反应性"换"实时性与连贯性"**，这是现代策略部署里最普遍的工程妥协。

#### 5.2 ACT（Action Chunking with Transformers）

把上面的思想做成具体架构：**基于 Transformer 一次性预测一个动作块**，配合**主从臂遥操作**的低成本双臂平台（ALOHA）采集数据。ACT 在论文中引入了一个很实用的技巧——**条件 VAE**：用隐变量 $z$ 吸收"同一任务的不同做法"这种多模态性，推理时把 $z$ 设为先验均值（即取一个"平均风格"），从而输出确定、平滑的动作序列。

它的重要性在于：**用相对便宜的双臂硬件 + 不太多的示教，就能完成插销、拉拉链、装电池这类精细操作**，证明了这条工程路线的可行性。

#### 5.3 扩散策略（Diffusion Policy）

**先看清它解决的是什么病**：普通回归头（L2 损失）的最优解是条件均值 $\mathbb{E}[a\mid o]$。如果同一观测下有两种都合理的做法（杯子可以从左边绕，也可以从右边绕），均值就是**穿过杯子**的那条路——在机器人上这不是精度问题，是撞车问题。

**扩散策略**把策略建模成一个**去噪过程**：训练时把真实动作加噪到近乎纯噪声，让网络学会预测所加的噪声；推理时从纯噪声出发，迭代去噪若干步，得到一条动作轨迹。

$$
\text{训练：}\;\; \mathcal{L} = \mathbb{E}_{a,\tau,\epsilon}\big[\|\epsilon - \epsilon_\theta(a^\tau,\tau,o)\|^2\big]
\qquad
\text{推理：}\; a^{T}\to a^{T-1}\to\cdots\to a^{0}
$$

**为什么能表达多峰**：它建模的是整个分布 $p(a\mid o)$ 而不是某个统计量。从不同的噪声样本出发，会收敛到**不同的模态**——同一画面下既能生成"从左边绕"也能生成"从右边绕"，而不是二者的平均。

**工程要点**：机器人扩散策略通常把**整个动作块作为整体去噪**（而不是逐帧独立去噪），时间连贯性由网络一次性保证，天然抑制了抖动。代价是推理要迭代多次前向（量级上常见个位数到几十步），用 DDIM 类加速采样、蒸馏成少步模型，或靠动作分块把时间摊薄。

#### 5.4 流匹配（flow matching）

扩散是"加噪—去噪"的逆向过程；流匹配直接学一个**速度场**，把简单分布沿近似直线的路径"流"到动作分布：

$$
\frac{d a^\tau}{d\tau} = v_\theta(a^\tau, \tau, o), \qquad \tau: 0 \to 1
$$

推理用数值积分（Euler 步进即可）。路径更直，所以**积分步数可以更少**（工程上常见几步到十几步），推理更快；训练目标就是简单的速度回归，比扩散更稳。π0 一类工作采用的就是流匹配动作头（具体配置**以原文为准**）。

**四者的关系一句话总结**：动作分块是"输出结构"的改进（一次出 $k$ 步），ACT 是"把分块做成 Transformer + 条件 VAE"，扩散与流匹配是"输出分布建模方式"的改进（能表达多峰）。它们可以叠加使用——现实中的强基线往往同时用了分块 + 生成式动作头。

### 6. 数据质量与规模：这一行的真相

- **质量 > 数量（尤其在小数据 regime）**：几十条干净、一致、覆盖多种初始位姿的示教，往往打败几千条抖动、标注错位、只有一种初始位姿的数据。**先修数据再换模型**，这是最高效的优化顺序。
- **数据多样性决定泛化**：物体外观、位置、光照、相机视角的多样性，直接决定模型出实验室后能不能用。
- **数据合成**：**MimicGen** 一类方法从少量人类示教出发，通过在仿真中改变物体与机器人初始状态自动生成大量成功轨迹，可显著缓解数据瓶颈；代价是合成数据与真实分布的差异需要额外验证。
- **失败数据也有价值**：可用于训练"失败检测/恢复"模块，或用于对比学习。但要注意别把失败动作当成功动作的目标去拟合。

### 7. 工程实践：用 LeRobot 跑通第一个 BC/ACT

**LeRobot** 是一个开源工程库，试图把这一堆零散环节标准化：统一的**数据集格式**、统一的**策略接口**、统一的**机器人接口**（真实与仿真）、以及一组现成的策略实现（含 ACT、扩散策略等）。对新手的价值是：**不用自己造数据格式和训练循环，能直接跑通"采数据 → 训练 → 部署"的完整链路**。

概念性流程（具体命令以官方文档为准）：

```
1. 装环境                 # 独立 conda/uv 环境，按官方 README
2. 准备机器人或仿真环境     # 无硬件可先用仿真或已公开数据集
3. 采集示教 / 下载数据集    # 遥操作若干次同一任务，注意初始位姿打散
4. 可视化检查数据           # 轨迹是否平滑、图像与动作是否时间对齐（关键一步）
5. 训练策略                # 例如 ACT；先小步数跑通，确认 loss 正常下降
6. 在仿真/真机上评测        # 多次试验，统计成功率，看失败视频
7. 分析失败模式            # 是视觉过拟合？初始分布太窄？动作抖动？
```

**最容易忽略的是第 4 步**。数据没对齐、动作单位错了、图像全是黑的——这些问题如果不检查，你会花三天调一个根本不该调的超参。

### 8. 评测：别只看"动作像不像"

模仿学习最危险的自我欺骗是**训练 loss 很低、部署完全不能用**。正确的评测方式：

- **闭环成功率**，而非动作的 L2 误差。动作误差小的策略完全可能任务失败（尤其是接近目标的最后几厘米）。
- **多次试验 + 打散的初始条件**（至少 20 次，报成功率而不是"演示的时候成功了"）。
- **看失败视频**：失败集中在哪种光照、哪种物体位置、哪个阶段？这决定下一步该补数据还是改模型。
- **测分布外（OOD）**：换没见过的物体、换背景、换位置，看掉多少。这才是泛化能力的真实读数。

## 动手练习

**练习 1：亲手制造一次分布偏移（numpy，可直接运行）。**

玩具任务：一维位置 `x`，目标是 1.0。专家策略是**非线性**的——越靠近目标，动作越小：

```python
import numpy as np

def expert(x):
    return -0.6 * (x - 1.0) ** 3        # 三次反馈：离目标越远，动作越大

def collect(lo, hi, n_episodes=300, steps=5):
    """让专家从 [lo, hi] 里的随机初始位置出发，采集示教数据"""
    X, A = [], []
    for _ in range(n_episodes):
        x = np.random.uniform(lo, hi)
        for _ in range(steps):
            a = expert(x)
            X.append(x); A.append(a)
            x = x + a                    # 真实环境：位置 += 动作
    return np.array(X), np.array(A)

def fit_linear(X, A):
    """行为克隆：拟合 a = w*x + b（最小二乘）"""
    M = np.stack([X, np.ones_like(X)], axis=1)
    return np.linalg.lstsq(M, A, rcond=None)[0]

def rollout(x, w, b, steps=60):
    for _ in range(steps):
        x = x + (w * x + b)
    return x

np.random.seed(7)
for lo, hi in [(0.0, 0.2), (0.0, 0.9), (0.0, 1.5)]:
    X, A = collect(lo, hi)
    w, b = fit_linear(X, A)
    x_end = rollout(0.0, w, b)
    print(f"示教范围 [{lo}, {hi}] → 学到 a={w:+.3f}x{b:+.3f}, "
          f"从 x0=0 出发 60 步后停在 x={x_end:.3f}")
print("（专家自己从 x0=0 出发，60 步后到 x≈0.888，且会继续逼近 1.0）")
```

你会看到类似这样的输出：

```
示教范围 [0.0, 0.2] → 学到 a=-0.783x+0.518, 从 x0=0 出发 60 步后停在 x=0.661
示教范围 [0.0, 0.9] → 学到 a=-0.505x+0.372, 从 x0=0 出发 60 步后停在 x=0.737
示教范围 [0.0, 1.5] → 学到 a=-0.194x+0.194, 从 x0=0 出发 60 步后停在 x=1.005
```

**读这个结果**：真目标是 1.0，专家能一路逼近；但只在小范围（[0, 0.2]）示教时，学到的线性策略把"目标"理解成 **0.661**——它**提前停下**，而且从任何初始位置出发都停在 0.661。因为在这段窄带里，"往右走一点"看起来就够了，它没有任何信息知道再往右还有更大的世界。

**把示教范围放宽到 [0, 1.5]，学到的策略就几乎正确了（1.005 ≈ 1.0）。** 这直接给出结论：**BC 学到的不是"任务"，而是"示教覆盖到的那些状态上的局部行为"**。数据没覆盖到的地方，它的外推完全没有意义——这就是分布偏移最朴素的样子。

试着把 `collect` 的 `steps` 从 5 改成 40（让专家走得更远、覆盖更多状态），观察误差是否进一步缩小。

**练习 2：动作分块的推理循环（伪代码，理解结构即可）。**

```python
def run_with_chunking(policy, env, k=8, exec_steps=4, max_steps=200):
    """policy(obs) -> 长度为 k 的动作序列"""
    obs = env.reset()
    for t in range(0, max_steps, exec_steps):
        chunk = policy(obs)                    # 一次推理，得到 k 步
        for a in chunk[:exec_steps]:           # 只执行前 exec_steps 步（滚动时域）
            obs, _, done = env.step(a)
            if done:
                return t
    return max_steps
```

改 `exec_steps = k` 就是"整块开环执行"，改 `exec_steps = 1` 就退化成逐帧推理。**亲手调这两个数，感受"反应性 vs 延迟"的权衡**，比读十遍文字深刻。

## 常见误区

1. **新手常以为"行为克隆就是监督学习，所以照着分类任务做就行"，其实是：它是闭环序列决策，必须防分布偏移。** 一定要给图像历史/本体状态、打散初始位姿、并做闭环评测。
2. **新手常以为"loss 降下去就等于学会了"，其实是：动作 L2 误差和任务成功率并不一致。** 最后几厘米的动作误差可能直接决定抓不抓得到，评测必须看闭环成功率与失败视频。
3. **新手常以为"数据越多越好"，其实是：一堆初始位姿单一、标注错位的数据会把模型训坏。** 先检查对齐与多样性，再考虑加量。
4. **新手常以为"扩散策略/流匹配更新，所以回归头过时了"，其实是：它们解决的是多模态问题，代价是推理慢。** 单峰、简单、要求高频率的任务里，回归头又快又稳，仍然常用。
5. **新手常以为"动作分块越长越好（推理更省）"，其实是：块越长，块内开环越久，反应性越差。** $k$ 是超参，要在延迟与反应性之间实测权衡。

## 自测题

**1. 什么是分布偏移？用"开车"或"背答案"打一个比方，并说明它为什么在 BC 里必然发生。**

<details><summary>点击查看答案</summary>

BC 只在专家产生的状态上训练，但部署时策略自身的微小误差会让机器人进入专家从不访问的状态；这些状态没有训练样本，模型输出无意义，误差进一步放大，形成自我放大的漂移。必然性来自：闭环系统中策略决定自己未来看到什么，而训练分布（专家轨迹）与部署分布（自身轨迹）从一开始就不一致。比方：只会背答案的学生遇到稍改数字的题就崩，且越慌越崩。

</details>

**2. DAgger 的核心思想是什么？为什么它在真机上难落地？**

<details><summary>点击查看答案</summary>

核心：让当前策略自己跑，收集它实际访问到的状态，再请专家为这些状态标注正确动作，合并进数据集迭代训练——即让训练分布逼近部署分布。真机难处：需要专家在线持续纠错/接管、低延迟、且策略早期动作危险需要安全兜底，人力成本高，因此常在仿真中做或做近似。

</details>

**3. 动作分块同时缓解了哪两个问题？它的主要代价是什么？怎么缓解这个代价？**

<details><summary>点击查看答案</summary>

缓解：① 推理延迟——一次前向可管 k 个控制周期，实时性预算放大 k 倍；② 复合误差——段内动作联合生成更自洽，推理次数减少 k 倍。代价：块内开环执行期间对突发变化（物体被移动、抓滑）无反应，且块边界可能不连续。缓解：时间集成、滚动时域（只执行前 m<k 步）、边界平滑。

</details>

**4. 为什么用 L2 损失训练的回归头无法表达"从左边绕或从右边绕"这两种做法？扩散策略凭什么可以？**

<details><summary>点击查看答案</summary>

L2 回归的最优解是条件均值 E[a|o]，当分布是多峰时均值可能落在两个模态之间——对机器人就是穿过障碍。扩散策略建模整个分布 p(a|o)，从不同噪声样本出发去噪会收敛到不同模态，因此能采样出多条彼此不同但都合理的动作。

</details>

**5. 你辛苦训了一个抓取策略，训练 loss 降到很低，但真机上 10 次只成功 2 次。列出你会依次检查的四件事。**

<details><summary>点击查看答案</summary>

① 数据质量与时间对齐（图像/动作时间戳是否一致、动作单位与语义是否正确、图像是否正常）；② 初始条件分布（真机评测的初始位姿/物体位置是否落在训练分布内，是否存在训练集只有单一初始位姿的问题）；③ 输入是否含历史与本体状态（单帧图像策略极易漂移）；④ 闭环细节（控制频率、动作限幅、推理延迟是否与训练时一致），并看失败视频定位失败阶段。最后才考虑换模型/加数据。

</details>
