# 强化学习与机器人

> 一句话导读：这篇讲清"让机器人自己试错学会做事"这件事的基本框架——状态、动作、奖励怎么定义，PPO/SAC 这类算法各自适合什么，以及为什么仿真里学会的本事搬到真机就崩。

## 正文

### 1. 直觉：不会写规则，就让它自己试

控制机械臂有两条路。第一条是人写规则："末端向杯子移动 3 厘米，然后闭合夹爪"。规则在实验室好使，换个杯子高度就失效——因为**你写不全**所有情况。

强化学习（Reinforcement Learning, RL）走另一条路：**定义一个打分标准，让机器人在环境里反复试，自己找出一套得分高的做法**。就像教狗坐下——你没法给狗讲清楚"臀大肌怎么发力"，但可以在它屁股着地那一瞬间给零食。

核心循环只有四步，机器人每秒重复几十次：

$$
\underbrace{o_t}_{\text{看到什么}} \;\to\; \underbrace{a_t \sim \pi(\cdot\mid o_t)}_{\text{做什么}} \;\to\; \underbrace{r_t, o_{t+1}}_{\text{得到反馈、看到新画面}}
$$

其中 $\pi$ 叫**策略（policy）**，就是我们要学的东西：一个从观测到动作的函数。

### 2. MDP：把"试错"写成数学

强化学习的形式化框架是**马尔可夫决策过程（Markov Decision Process, MDP）**，五元组 $(S, A, P, R, \gamma)$：

| 符号 | 含义 | 用"机械臂抓杯子"具体化 |
|---|---|---|
| $S$ | 状态空间 | 关节角、末端位姿、杯子位置、夹爪开度、图像 |
| $A$ | 动作空间 | 每个关节的位置增量，或末端位姿增量 + 夹爪开合 |
| $P(s'\|s,a)$ | 状态转移（物理规律） | 给定力矩，接触力把杯子推走多少；**你通常不知道，也不可微** |
| $R(s,a,s')$ | 奖励 | 杯子被抬起 +1，撞翻 −1，每步耗时 −0.01 |
| $\gamma$ | 折扣因子（0~1） | 未来奖励的折扣；越接近 1 越"有耐心"，越看长期 |

"马尔可夫"三个字的意思是：**当前状态包含了做决策所需的全部历史信息**。这在真机上很少成立（杯子可能被手挡住了，你只看到一部分），所以实际系统用的是**部分可观测 MDP（POMDP）**，工程上的补救办法很朴素：把最近几帧图像和关节历史一起塞进状态，让"状态"近似够用。

目标是找到策略 $\pi$ 最大化期望回报：

$$
J(\pi) = \mathbb{E}_{\pi}\left[\sum_{t=0}^{T} \gamma^t r_t\right]
$$

**两个必须分清的量和**：

- **价值函数 $V^\pi(s)$**：从状态 $s$ 出发，按策略 $\pi$ 走下去，期望能拿多少回报（"这局面有多好"）。
- **动作价值函数 $Q^\pi(s,a)$**：在状态 $s$ 先做动作 $a$、之后按 $\pi$ 走，期望回报（"这个动作在局面下有多好"）。

学 $Q$ 是为了改进策略：$\pi'(s) = \arg\max_a Q^\pi(s,a)$。所有主流算法都是"估计价值 → 改进策略"的某种循环。

**探索与利用（exploration vs exploitation）**：只在已知好动作附近磨，会卡在次优解；乱试又学不到东西。常用手段是给动作加噪声、用随机策略采样，或在熵上给奖励（SAC 的核心思想）。

### 3. 奖励设计：RL 落地的第一痛点

奖励是唯一告诉机器人"什么算好"的东西，也因此最容易被钻空子。

**稀疏奖励（sparse reward）**：只有成功时才给 +1，其余全 0。问题不是"学得慢"，而是**几乎学不到**——随机探索几千次都碰不到一次成功，梯度里没有任何信息。缓解手段：

- **奖励塑造（reward shaping）**：加中间奖励，比如"末端离杯子越近给越多"。这是最常用也最危险的手段。
- **课程学习（curriculum）**：先把杯子放得近、目标放宽，逐渐加难。
- **模仿学习初始化 / 示教数据**：用人演示把探索"抄近路"。
- **事后重标注（hindsight relabeling）**：失败了也没关系，把"实际到达的位置"当成新目标重新算奖励（HER 一类方法的思路）。

**奖励黑客（reward hacking）**：智能体会精确地优化你写的奖励，而不是你心里的那个目标。经典例子——想让它"把杯子放到盘子上"，你写了"杯子与盘子距离最小化"，结果它学会了**把杯子推下桌子**，因为掉落过程中两者距离确实变小过。再如"让机器人快速移动"，它学会高频抖动（移动速度峰值大，净位移为零）。

工程上的纪律：**每加一项奖励，都要预演"最坏情况它会怎么钻空子"**，并把终止条件（打翻、越界、撞人）设成硬失败，而不是靠惩罚项软性阻止。

### 4. 算法地图：别按排名选，按场景选

| 算法 | 动作空间 | on/off-policy | 样本效率 | 定位与适用场景 |
|---|---|---|---|---|
| DQN | 离散 | off-policy | 中 | 离散动作（开关、选项）。连续控制不适用 |
| 策略梯度（REINFORCE） | 连续/离散 | on-policy | 很低 | 教学与基线，理解"策略梯度"从这开始 |
| A2C / A3C | 连续/离散 | on-policy | 低 | 并行环境、快速迭代；实践中常被 PPO 取代 |
| **PPO** | 连续/离散 | on-policy | 中 | **机器人领域默认起点**：实现简单、稳定、好调、支持连续动作 |
| DDPG | 连续 | off-policy | 较高 | 确定性策略，早期连续控制方案，对超参敏感 |
| **TD3** | 连续 | off-policy | 较高 | DDPG 的修正版（双 Q、延迟更新、目标平滑），更稳 |
| **SAC** | 连续 | off-policy | 高 | 最大熵框架，探索好、样本效率高，真机/仿真都常用 |
| 基于模型（Dreamer 一类） | 连续/离散 | — | 很高 | 先学世界模型再在"想象"里训练，适合样本极贵场景 |

**为什么机器人领域默认 PPO**：它把"策略更新幅度"限住了（用重要性采样比率裁剪），避免一次糟糕更新把策略毁掉；对超参不那么敏感；连续动作支持成熟。代价是**样本效率低**——它只看当前策略产生的数据，用完就丢，所以通常要成千上万个并行仿真环境喂它。

**为什么真机更偏 SAC/TD3**：真机采样很贵，需要 off-policy 算法反复利用历史数据（存进回放池 replay buffer）。

**连续动作的实现细节**：策略网络输出高斯分布的均值 $\mu$ 与标准差 $\sigma$，采样得到 $a$，再用 $\tanh$ 压到 $[-1,1]$ 后按动作范围缩放：

$$
a = a_{\min} + \frac{\tanh(z)+1}{2}(a_{\max}-a_{\min}), \qquad z \sim \mathcal{N}(\mu, \sigma^2)
$$

注意 $\tanh$ 会改变分布形状，计算对数概率时必须加**雅可比修正**项（否则梯度是错的），这是手写实现最常见的 bug。

### 5. 仿真训练，真机执行：sim2real

这是 RL 进入物理世界的必经关卡。仿真里完美，真机上稀碎，原因可以逐条列出：

| reality gap 来源 | 仿真里通常怎样 | 真机上实际怎样 |
|---|---|---|
| 摩擦与接触 | 库仑摩擦系数随手填 | 干摩擦、静摩擦、黏滑、接触面磨损 |
| 延迟 | 动作立刻生效 | 通信 + 控制器 + 执行器带来几十毫秒延迟 |
| 质量与惯量参数 | URDF/MJCF 上的名义值 | 线缆、负载、装配公差导致的偏差 |
| 执行器非线性 | 理想力矩源 | 电流限幅、齿隙、温漂、减速器柔性 |
| 观测差异 | 完美关节角、干净渲染图 | 编码器噪声、图像曝光/反光/纹理差异 |

**三板斧**：

1. **域随机化（domain randomization）**：训练时随机化物理参数（质量、摩擦、延迟）与视觉外观（纹理、光照、相机位姿），让策略见过足够多的"可能世界"，真机只是其中一个样本。**治的是"参数不准"**。
2. **系统辨识（system identification）**：反过来，先测真机参数（用摆锤实验测惯量、用阶跃响应测延迟），再把仿真校准到接近真机。**治的是"参数太离谱"**，与域随机化互补（先辨识出中心，再在其附近加随机化）。
3. **观测/动作空间对齐**：保证仿真与真机的相机内参视角、图像预处理、动作单位、控制频率一致。**治的是"接口不一致"**——这一类 bug 最多、最蠢、最容易漏。

**实操顺序建议**：先做第 3 条（便宜且必做），再做系统辨识拿到名义参数，最后才上域随机化。反过来做的话，你会在错误的仿真上随机化半天。

### 6. RL 还是模仿学习？

| 维度 | 强化学习 | 模仿学习（见 [05](./05-模仿学习与示教.md)） |
|---|---|---|
| 数据来源 | 自己试错（真机极贵、仿真便宜） | 人类示教 |
| 需要什么 | 一个好奖励函数 | 一批好示教数据 |
| 样本效率 | 低（常需百万级交互） | 高（几百条示教常够用） |
| 能力上限 | 可能超过人类 | 大致不超过示教水平 |
| 主要失败模式 | 奖励黑客、训练不稳定 | 分布偏移、对未见场景脆弱 |
| 真机风险 | 试错可能撞坏东西 | 相对安全 |

**当前的真实格局**：真机操作任务（抓取、装配、叠衣服）大量用模仿学习，因为它不需要奖励设计、不需要危险试错；足式运动（四足、人形行走）和精细手内操作则大量用 RL，因为这类任务人类难以示范、且奖励（别摔倒、往前走）容易写清楚、还特别需要在仿真里大规模并行试错。

一句话：**奖励容易写、仿真可信 → 用 RL；人能示范、任务多样 → 用模仿学习。** 现在很多系统两者混用：先用示教做初始化，再用 RL 微调（或反之）。

### 7. 别忘了评测

RL 结果对随机种子极其敏感，而论文常报"挑出来的最好一次"。自己评估时必须做到：

- **至少 3~5 个随机种子**，报均值 ± 标准差，别只跑一次。
- **固定评测环境**：评测时的初始状态分布要写清（随机的还是有固定的几个）。
- **区分训练曲线和最终性能**：训练时的高回报可能是探索噪声带来的假象。
- **记录失败案例**：机器人为什么失败，比成功率涨了几个点更有信息量。

## 动手练习

**练习 1：用 PPO 训练倒立摆（需要 `pip install stable-baselines3 gymnasium`）。**

```python
from stable_baselines3 import PPO
from stable_baselines3.common.env_util import make_vec_env

# Pendulum-v1：连续动作（力矩），状态是 [cosθ, sinθ, θ̇]
env = make_vec_env("Pendulum-v1", n_envs=4, seed=0)

model = PPO("MlpPolicy", env, verbose=1, seed=0,
            learning_rate=3e-4, n_steps=1024, batch_size=64, gamma=0.98)
model.learn(total_timesteps=100_000)
model.save("ppo_pendulum")

# 看效果：``tensorboard --logdir ./ppo_pendulum_tensorboard``（需在 learn 时指定 tensorboard_log）
obs = env.reset()
for _ in range(200):
    action, _ = model.predict(obs, deterministic=True)
    obs, reward, done, info = env.step(action)
```

观察三件事：① 前 1 万步几乎不动（随机探索）② 奖励曲线出现台阶式上升 ③ `deterministic=True` 时不抖、`False` 时抖——这就是探索噪声的直接体现。

**练习 2：手写 REINFORCE，看清策略梯度的样子。**

```python
import gymnasium as gym
import numpy as np
import torch
import torch.nn as nn

env = gym.make("CartPole-v1")
net = nn.Sequential(nn.Linear(4, 64), nn.ReLU(), nn.Linear(64, 2))
opt = torch.optim.Adam(net.parameters(), lr=1e-2)

for episode in range(500):
    logps, rewards = [], []
    obs, _ = env.reset(seed=episode)
    done = False
    while not done:
        logits = net(torch.as_tensor(obs, dtype=torch.float32))
        dist = torch.distributions.Categorical(logits=logits)
        action = dist.sample()
        logps.append(dist.log_prob(action))
        obs, r, terminated, truncated, _ = env.step(action.item())
        rewards.append(r)
        done = terminated or truncated

    # 回报（这里没折扣，CartPole 每步 r=1，所以回报=剩余步数）
    returns = torch.tensor(rewards, dtype=torch.float32)
    returns = (returns - returns.mean()) / (returns.std() + 1e-8)   # 关键：标准化
    loss = -(torch.stack(logps) * returns).sum()
    opt.zero_grad(); loss.backward(); opt.step()

    if episode % 50 == 0:
        print(f"episode {episode}, 存活步数 {len(rewards)}")
```

注意 `returns` 标准化那行——**去掉它，训练会极不稳定**。因为原始回报恒为正，所有动作的 log 概率都会被一起推高，只是幅度不同。

**练习 3（思考题，不用写代码）**：想用 RL 训练"机械臂把易拉罐扔进垃圾桶"。写出你的奖励函数，然后自己攻击它——找一个智能体可以靠钻空子拿高分而不真正完成任务的办法。你多半会想到"把罐子搬到垃圾桶正上方然后松手但没进去"。这说明什么？

## 常见误区

1. **新手常以为"奖励越细越好、每步都给分"，其实是：越细的奖励越容易被钻空子。** 优先写"任务是否完成"这类可验证的终局判据，中间奖励只在必要时加，且要预演它能怎么被 hack。
2. **新手常以为"RL 训练不收敛一定是算法选错了"，其实是：80% 的问题是环境接口 bug。** 动作范围没缩放、观测没归一化、`terminated` 和 `truncated` 混用、目标值泄漏进观测——先查这些，再换算法。
3. **新手常以为"仿真里成功率 95%，真机就能用"，其实是：sim2real 才是主要工作量。** 尤其是观测对齐（相机内参、图像预处理）这类低级问题，能吃掉一半时间。
4. **新手常以为"PPO 是 SOTA 所以什么都用 PPO"，其实是：PPO 胜在稳定和好调，不是样本效率。** 真机上采样贵，off-policy 的 SAC 往往更实际；大规模并行仿真里 PPO 才发挥最大优势。
5. **新手常以为"奖励涨了就是学会了"，其实是：可能是钻空子或探索噪声假象。** 一定要看**行为视频**，并做 `deterministic=True` 的评测。

**4. reality gap 的五个来源是什么？域随机化、系统辨识、观测对齐各治哪一个？**

<details><summary>点击查看答案</summary>

来源：摩擦与接触模型、延迟、质量惯量参数偏差、执行器非线性（限幅/齿隙/温漂）、观测差异（噪声、图像外观）。域随机化治"参数不准"（让策略见过多种可能世界）；系统辨识治"参数太离谱"（先从真机测出名义参数）；观测/动作对齐治"接口不一致"（相机内参、预处理、单位、频率）。建议顺序：先对齐接口，再辨识，最后随机化。

</details>

**5. 给定两个任务：① 四足机器人学会在碎石路上快走；② 桌面机械臂按语音指令收拾玩具。分别优先选 RL 还是模仿学习？为什么？**

<details><summary>点击查看答案</summary>

① RL：奖励（前进速度、姿态稳定、不摔倒）容易写清，且能在仿真中大规模并行试错，人类也难以示范四足的运动技能。
② 模仿学习：任务多样、指令开放，奖励难写（"收拾好"无法简单量化），而人类遥操作示教现成；同时真机试错撞坏东西的风险太高。现实中常混合：示教初始化 + RL 微调。

</details>
