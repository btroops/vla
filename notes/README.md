# notes/ —— 我自己的学习笔记

> 这里放"**我写的**"笔记，不是抄别人的内容。
> 判断自己有没有学会的唯一标准：能不能用大白话写给三个月后的自己看。

## 一、目录与命名

```
notes/
├── 2026-11-23-se3-左乘右乘.md      # 单次学习笔记：YYYY-MM-DD-主题.md
├── 2026-11-30-第一次跑通mujoco.md
└── weekly/
    └── 2026-W48.md                 # 每周复盘：YYYY-W周号.md
```

- 主题用小写英文或简短中文，**不要空格**。
- 一篇文章只记一件事。写长了就拆。
- 日期用**开始记的那天**，不是完成那天。

---

## 二、笔记的三层，别混在一起

| 层 | 写在哪 | 要求 | 时长 |
|----|--------|------|------|
| ① 速记 | 随手（临时文件/纸） | 只求不丢，错别字无所谓 | 实时 |
| ② 概念卡 | `notes/YYYY-MM-DD-主题.md` | 一条 = 一个概念，用自己的话 | 当天 |
| ③ 输出 | 整理成能讲给别人听的文章（可并入 `docs/`） | 有类比、有例子、有边界条件 | 每周末 |

**跳过 ① 直接写 ② 是常见错误**：想不起来当时想到什么，结果笔记只剩一句"今天学了 XX"。

## 三、有效的技术笔记长什么样

### 1. 费曼技巧（Feynman Technique）
学完立刻试着向"完全不懂的人"解释这个概念。一旦解释卡壳，**卡壳处就是你没真懂的地方**——回去补，然后重新解释一遍。

具体操作：写完笔记后盖住内容，口述 60 秒。说不下去就回去补那一段。

### 2. 概念卡：一卡一概念
每张卡只回答四个问题：
- 它**解决什么问题**（不写这个，你以后会记成一串公式）
- 它的**核心机制**（一句话 + 一个公式/流程图）
- 它的**适用边界**（什么时候不该用它）
- 一个**具体例子**（最好是你跑过的那个场景）

### 3. 坑本（最有价值的一本）
单独维护一段"我踩过的坑"，格式固定：

```
现象：ModuleNotFoundError: libmujoco.so.3.1: cannot open shared object file
环境：conda py3.10 / mujoco 3.1.x / WSL2 Ubuntu 22.04
根因：pip 装的 mujoco 与 conda 的 GL 库混装
解决：conda install -c conda-forge mujoco（先 remove pip 版）
耗时：1.5 小时    可避免性：高（先看官方 install 文档）
```

为什么值得记：报错搜到的答案常常版本不对，而**你自己环境里的那条**才是对的。

### 4. 概念之间的关系比概念本身重要
每篇笔记末尾加一段"**它和谁有关**"：前置是什么、和哪个概念容易混、在哪个项目里用过。这块写不出来，说明你只是记住了名词。

## 四、每周复盘（15 分钟）

每周固定时间写 `notes/weekly/YYYY-Www.md`，回答 5 个问题：
1. 这周实际做了什么（**可运行产物**是什么，没产物就诚实写"没有"）
2. 学到的三个新概念（各一句话）
3. 卡在哪、卡了多久、怎么解决的
4. 下周的**一个**具体目标（能量化验收的）
5. 一句总结（这周算"进步"还是"原地打转"，为什么）

> 复盘的重点不是记录，而是**发现自己在哪类事情上反复卡住**。如果连续三周都卡在环境/配置，那就该换条技术路线，而不是继续硬扛。

---

## 五、避免把笔记写成"资料的搬运"

| 别这样 | 要这样 |
|--------|--------|
| 复制粘贴论文摘要 | 用一句话说出"它解决什么问题" |
| 抄一堆公式 | 抄一个公式 + 解释每个符号 + 说清什么条件下成立 |
| 只记结论 | 记结论 + 怎么验证的（跑了什么、看到什么） |
| 通篇正确但没重点 | 标出"我原来以为 X，其实是 Y"这种**认知更新点** |

最后一条最重要：**笔记的价值在"认知更新"，不在"信息完整"**。完整的信息 arXiv 上和文档里都有。
